# Non-functional requirements

## Privacy

Participant identity never leaves the source adapter's table. Runner ids are opaque. Event replay (what the person does on the page; typing is kept without its values) is always recorded, and the consent says so; screen video is opt-in per study with `record: 'video'` and asked for by the browser; voice and camera are always the person's choice, the camera off unless they turn it on. Recordings are stored in the author's own storage: the store of the author's ui-tests server on the runner track, the author's bucket on the author's deploy (R2 on the first provider, Cloudflare Workers), never on ui-tests.com. Default retention is 90 days on both tracks, and a withdrawal deletes them. The player masks password and payment fields in events by default. Fixture data is synthetic; the lint warns when a scenario references a real-looking email or name outside the fixture. The device and IP hash used for duplicate detection is salted per project and never exported. The tag records only while a person who has said yes is in an attempt, and the visitors source keeps nothing from before a visitor accepts an invitation.

## Security

Panel tokens and the collector secret come from the environment, or on the author's deploy from the token `ui-tests host --panel` keeps there, and are never written to the run record, the trace, or the repository. The collector accepts writes only from a valid participant token issued at invite, scoped to one run, or from the CLI secret; this holds behind a tunnel, inside a perimeter and on a public preview alike, so a tunnel URL by itself opens nothing. Tunnels close at the run's deadline or when the process exits, and their URLs are recorded in the trace.

The tag on the author's page loads `ui-tests.js` only from the origin in its own `data-ui-tests`, only when that is an absolute http(s) address, and only when the page carries a handoff code or an unexpired attempt for that same server; no link can name another server, so a crafted link cannot make the author's page run someone else's script. The participant token never reaches the author's page. The player hands the person into the app with a one-time handoff code in the URL fragment (`#ui-tests=<run>.<code>`), which browsers never send to the app's server; the code is valid for 60 seconds and one exchange, and the tag takes it out of the address before anything else runs. The loader trades it at the collector for an attempt key, kept in `localStorage` on the app's origin for every tab of the app, that lasts two hours, is bound to that one attempt and can do only what the bar does: read the bar's view and send events, replay, video, the first click, the step, more time and the end. Anything else with an attempt key is refused; answers, withdrawal and reading the study stay with the player on the server's origin, behind the token and its cookie. Ending or withdrawing clears the key. The participant's cookie is scoped to `/api/ui-tests/`, and the front door never sends a `ui-tests-*` cookie to the app. Behind the front door (`recruit --tunnel` or `--host`) the app shares the server's origin, so a script on the app's pages can call the collector with the participant's cookie and act as the participant; that is the front door's limit, and a run where it matters reaches the server on its own origin. The collector accepts cross-origin calls only from the origins stored with the run (its target, preview or front-door address), only with an attempt key or at the exchange, and never with credentials. The player bundle contains no hooks, no happy paths, no expected answers and no panel credentials. Hooks run in the runner. Trace and report pages are reachable only with the author's session or a signed link the author created: the path signed with an HMAC under `UI_TESTS_SHARE_SECRET`; without the secret there are no share links.

## Money

Amounts are integers in minor units with a currency. States are estimated, reserved, paid, trued-up. The cap is enforced before every publish and includes the reserve for the raise rule and the true-up. The store's reservation is transactional; a storage adapter that cannot do that is not an adapter. Nothing retries a publish without first reading the source for the outcome of the last one. The visitors source's cap per day is enforced before every invitation. Pay for `link` participants, when the author sets it, is the author's to send: it is recorded as owed per attempt and never reserved from a panel balance.

## Accessibility

The player passes axe with no violations and is operated end to end with keyboard only and with VoiceOver on Safari. Time limits are generous by default and the participant can request more time once without penalty. A participant's assistive technology is recorded and reported with the issues they hit, never treated as a quality problem.

## White label

Everything a participant or a visitor sees is the author's, not ours. The taskbar, the scenario card, the consent, the questions, the visitors invitation on the author's deploy and the shareable report page carry the author's name, and the logo, colours and font of the config's `brand`, stored with the run when it is created. Without a brand the bar takes its colours and type from the host page and the server's pages use a neutral default theme. No ui-tests logo, name or link appears on a participant-facing surface: the bar, the player, the report or the server's page titles. The taskbar is visually subordinate to the host page: small, fixed, movable, never covering primary content, and styled as a distinct overlay, the inverse of the host page with the author's font and accent, never sharing the host page's panel colour. The intercept invitation in particular must read as the site asking, because a stranger's badge on a struggling visitor's screen is the surest way to be declined. The author's own review surfaces, the trace viewer and the dashboard, may carry our brand.

## Performance and reliability

Dev mode opens in under five seconds on a fresh clone. The tag costs the author's page nothing without a person in an attempt: its inline script is at most 700 characters and makes no request and no change to the page. With one, the loader it fetches is at most 8 KiB and carries neither React nor rrweb; the bar, the recorder and, when the study records them, the replay and the screen video load after it, from assets named by their content. The collector stores an attempt's events in bounded batches with an IndexedDB retry buffer in the participant's browser, so a dropped connection does not lose an attempt while the page stays open: buffered events are replayed when the collector is reachable again, and discarded if the person closes the page first. The buffer does not survive the participant leaving, and nothing is buffered on the collector's side. A disconnected attempt is `disconnected`, never `incorrect`.
