# The site schema: content types, components and layout rules

The site in `apps/web` is a static export: the landing page and the docs pages (`/docs/getting-started`, `/docs/agents`, `/docs/reachability`). The report at `/r/<run>` and each attempt at `/r/<run>/p<n>` are pages of the ui-tests server, rendered by `ReportView` (`packages/ui-tests/src/report/view.tsx`); the `RunReport` and `Attempt` rows below describe them. The words come from the research ([`../discovery/reporting-schema-research.md`](../discovery/reporting-schema-research.md), [`../discovery/contract-to-study-research.md`](../discovery/contract-to-study-research.md), [`../discovery/sources-research.md`](../discovery/sources-research.md), [`../discovery/sources-desk-research.md`](../discovery/sources-desk-research.md), [`../discovery/pull-request-surfaces-research.md`](../discovery/pull-request-surfaces-research.md), [`../discovery/report-presentation-research.md`](../discovery/report-presentation-research.md), [`../discovery/agent-section-research.md`](../discovery/agent-section-research.md), [`../discovery/roi-research.md`](../discovery/roi-research.md)), and each section's layout and words from its artefact in [`../../design/artefacts/`](../../design/artefacts/README.md), on one grid ([`../../design/artefacts/README.md`](../../design/artefacts/README.md#the-page-grid-in-one-place)).

**Theme rule.** The site is light only, whatever the system setting: the tokens are [`../../design/artefacts/tokens.css`](../../design/artefacts/tokens.css), the ground is ink #111111, one accent #4b3ff0, line #e2e2e2, canvas #f6f6f6 and white, and the data roles (moment #b84d00, stop #8b6100, nothing happened #bd1f44, reached #007852, words #7a41af; code: keyword #7444b4, string #27762f, property #00757c) are derived in OKLCH around the accent, each at 4.5:1 or better on the canvas. `globals.css` carries the light block of `tokens.css` alone, with `color-scheme: light` and the matching meta, so form controls and scrollbars are light too; nothing on the site reads `prefers-color-scheme` or `data-theme`. The artefacts carry the Tokyo Night block as the viewer's dark alternate, not the site's. Colour stays on the data; chrome is neutral: the accent carries links, buttons, the person marks and off your path; the moment carries the moment to watch, slowed and ranks. The site's own surfaces (the attempt view, the report, the sections, the terminal and code windows) are white windows on the canvas with the line colour as their edge, and GitHub's chrome is drawn in the site's neutrals; the demo app under test keeps its own light grey. The participant chrome (scenario card, bar, recording state, question sheets) is the inverse of its host page with the author's accent, so over the light demo app it is dark with Weekboard's mint. The rules are written once, in [`../../design/artefacts/README.md`](../../design/artefacts/README.md#theme-rules-in-one-place); the rows below do not restate them.

The pages are built from content types, each rendered by one component with one layout rule. A block is a sequence of typed content, not a hand-drawn layout. The grid is 12 columns on a 1248px container with 24px gutters, 96px margins at 1440 and 16px on a phone; at 375 everything stacks in source order. Every landing section's heading takes the first five columns and its lead the right seven (a 5fr / 7fr split with one gutter: the heading at 96, 510 wide; the lead at most 64ch, ending flush at 1344), and every figure takes all twelve columns or the right seven; nothing is centred in a narrower column. `tests/e2e/grid.spec.ts` measures every section's heading, lead and figures against this at 1440 and 375.

### Page composition

Landing: Claim; WhatComesBack (how it works); Compilation (what you write, what they see); Sources (where the people come from); Worth (what a run is worth); Agents (the agent section); Host (your server, one command). There is no commands block and no "this page runs this test" code file; the commands are the Compilation's list. Docs: getting started, agents and reachability, each a docs page. Report, on the ui-tests server: the list at `/r/<run>`, each person's attempt at `/r/<run>/p<n>`.

Every page in the site shell (the landing and the docs pages) has the page's texture behind it and closes with the footer: the wordmark, then "miguel.design", "Open source MIT licence" and "Report a bug or suggest an improvement". The report, the shared report links and the participant player are the ui-tests server's and carry neither.

### Rules that apply to every component

- One component per content type; no block invents its own layout.
- Themes follow the theme rule at the top of this file and nothing else: every component reads the tokens only, no component carries a literal colour or a theme of its own, and `tests/contrast.test.ts` holds every text token and data role on the site at its floor in the light theme (and both blocks of `tokens.css` for the artefacts).
- Empty area in a block never exceeds the area of its artefacts; a side caption never has a column to itself wider than its text needs.
- Hover and focus change paint only.
- Every component that owns chrome (`TerminalWindow`, `LinesWindow`, the merge box and the check page in `WhatComesBack`, the report and the attempt in `ReportView`, the host section's terminal) renders the label "Example run" once in that chrome whenever its content is from the example run; the label is a property of the chrome component, set by the page, not a field on the content types, so it is never omitted or duplicated.

### Words

Every surface that shows an attempt's data (the trace data, the Ink renderer, the HTML fragment, the report, the pull-request check and the landing copy) uses these words: Person 3 (of 5), paid panel, Reached the goal (Yes / No / Couldn't tell), How it ended (pressed Done / pressed I couldn't do this / ran out of time / withdrew / left), "Wrong, and sure" only at 7 of 7 and not reached, How easy was it? (7 = very easy), How sure they'd done it (7 = completely sure), Time on this goal, Off your path, Went back, Stopped n s, "<action>, nothing happened", and "Pressed Done" as the last row of the flow. Impact is blocked, slowed or confused; on an attempt that did not reach the goal, the moment that produced the end state is "wrong end state". The run's after-goal answers appear once, on the run: "Would it help them? 4 of 5 · Easy to use? 2 of 5". Also: "Person 3 · 00:03", never "P3"; "Moments", never a "Watch" column; "Suggested change", never "What to change"; the result line "Problems found: 4, seen across all 5 people"; "Pressed Done, but your check failed: x of n" on a goal with a check, "Wrong, and sure" only on a goal without one at 7 of 7; the impact legend "Blocked kept them from the goal · Slowed cost them time · Confused did something that had no effect" on first use; "paid panel (Prolific)" (the panels the people came from) on first use; "Who took part" and "First look" for fit and impression; and the caveat "Found automatically from what people did; it can miss problems. Watch the clips." No surface weighs a run in these words: never "ROI", "rule of ten", "studies show", "doubles conversion" or "saves money"; a run is weighed in a developer's time, from the BLS figures, with the arithmetic shown and editable (the `Worth` row). The check is `ui-tests`, its mark neutral; an agent run's check is `ui-tests (agent)`, and nothing calls an agent run usability testing. `tests/vocabulary.test.ts` holds the list, the worth words as `unsaid`.
