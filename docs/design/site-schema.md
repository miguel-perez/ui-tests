**Theme rule.** The site is light (issue #38): the tokens are [`../../design/artefacts/tokens.css`](../../design/artefacts/tokens.css), the ground is ink #111111, one accent #4b3ff0, line #e2e2e2, canvas #f6f6f6 and white, and the data roles (moment #b84d00, stop #8b6100, nothing happened #bd1f44, reached #007852, words #7a41af; code: keyword #7444b4, string #27762f, property #00757c) are derived in OKLCH around the accent, each at 4.5:1 or better on the canvas. The Tokyo Night palette is the dark alternate, under the system setting and `data-theme="dark"`. Colour stays on the data; chrome is neutral: the accent carries links, buttons, the person marks and off your path; the moment carries the moment to watch, slowed and ranks. The site's own surfaces (the attempt view, the report, the sections, the terminal and code windows) are white windows on the canvas with the line colour as their edge, and GitHub's chrome is drawn in the site's neutrals; the demo app under test keeps its own light grey. The participant chrome (scenario card, bar, recording state, question sheets) is the inverse of its host page with the author's accent, so over the light demo app it is dark with Weekboard's mint. The rules are written once, in [`../../design/artefacts/README.md`](../../design/artefacts/README.md#theme-rules-in-one-place); the rows below do not restate them.

The pages are built from content types, each rendered by one component with one layout rule. A block is a sequence of typed content, not a hand-drawn layout. The grid is 12 columns on a 1248px container with 24px gutters; at 375 everything stacks in source order.

### Page composition

Landing: Claim; Section + Attempt (what comes back); Compilation (what you write, what they see); Sources (where the people come from); Section + ChecksBox + FindingsList (in the pull request); Section + AgentRun (the agent); Section + Snippet + Dashboard (the hosted track). There is no commands block and no "this page runs this test" code file; the commands are the Compilation's cards. Guide: Step × 6, then the "Without a repository" track as Step × 2.

### Rules that apply to every component

- One component per content type; no block invents its own layout.
- Themes follow the theme rule at the top of this file and nothing else: every component reads the tokens only, no component carries a literal colour or a theme of its own, and `tests/contrast.test.ts` holds every text token and data role at its floor in both themes.
- Empty area in a block never exceeds the area of its artefacts; a side caption never has a column to itself wider than its text needs.
- Hover and focus change paint only.
- Every component that owns chrome (`TerminalWindow`, `CodeWindow`, `AttemptView`, `ReelFrame`, `FindingsList`, `ChecksBox`, `Dashboard`) renders the label "Example run" once in that chrome whenever its content is from the example run; the label is a property of the chrome component, set by the page, not a field on the content types, so it is never omitted or duplicated.

### Words

Every surface that shows an attempt's data (the trace data, the Ink renderer, the HTML fragment, the report rows, the pull-request check, the dashboard and the landing copy) uses the words of issue #22: Person 3 (of 5), paid panel, Reached the goal (Yes / No / Couldn't tell), How it ended (pressed Done / pressed I couldn't do this / ran out of time / withdrew / left), "Wrong, and sure" only at 7 of 7 and not reached, How easy was it? (7 = very easy), How sure they'd done it (7 = completely sure), Time on this goal, Off your path, Went back, Stopped n s, "<action>, nothing happened", and "Pressed Done" as the last row of the flow. Impact is blocked, slowed or confused; on an attempt that did not reach the goal, the moment that produced the end state is "wrong end state". The run's after-goal answers appear once, on the run: "Would it help them? 4 of 5 · Easy to use? 2 of 5". `tests/vocabulary.test.ts` holds the list.
