# What participants see in unmoderated usability tests: product audit, evidence and a specification

Date: 16 October 2026. Method note: all product findings come from vendor help centres, demo/transcript pages, and (where the help centre blocked fetches) search-index snippets of those help pages. UserTesting's help centre (help.usertesting.com, support.usertesting.com) and Useberry's help centre (useberry.zendesk.com; help.useberry.com does not resolve) returned 403, so those two entries are built from indexed snippets and secondary sources and are marked accordingly. "Not documented" means the fetched docs do not say, not that the feature is absent.

## Part 1: Products

### Maze (prototype test and live website test)
Sources: https://help.maze.co/articles/6187908027-prototype-test-interacting-with-a-prototype-test, https://help.maze.co/hc/en-us/articles/7032915518611, https://help.maze.co/hc/en-us/articles/46070670578067-Interacting-with-a-Website-Test-revised, https://help.maze.co/hc/en-us/articles/5461211386515 (Clips permissions), https://help.maze.co/hc/en-us/articles/360051963934 (skippable blocks)

- Task presentation: a full-screen intro screen shows the task and description with a "Get started" button. Once the task starts, the instructions become a small movable modal, by default bottom-left on desktop; it collapses automatically after the first interaction with the prototype. For mobile prototypes viewed on desktop the task sits in a fixed left side panel. On a phone, task controls are a bottom panel with "Hide instructions".
- In-task controls: "End task" (website test) or "Abandon task" / "Stop task" (prototype, free-explore). The give-up control is deliberately hidden until the participant has interacted at least once, "to prevent testers from giving up without attempting". Goal-based prototype tasks end automatically on reaching the success screen; website tasks never auto-end and show no success message, so creators are advised to remind participants to click "End task" in the task text. A "Drag" handle moves the modal. Clips adds a mic mute toggle and a pause on the camera thumbnail ("Resume task").
- Re-opening task text: on mobile a ">" button bottom-left brings the instructions and "Abandon task" back; on desktop the collapsed modal stays on screen.
- Progress: not documented in the fetched articles.
- Post-task questions: separate blocks (opinion scale, multiple choice, open question, yes/no) after the task; question blocks are required by default, and only non-required ones show a "Skip" button. Tasks themselves cannot be made optional.
- Consent and recording: a pre-test note lists which permissions are optional or required; after "Get started" the browser prompts for mic, camera, screen share; live website tests require sharing the entire screen; an optional think-aloud instruction video; a confirmation modal of recording settings with "Start test". Non-anonymised studies show the warning "All personal data shown on-screen and data you enter will be viewable by the test creator." No persistent recording indicator is documented beyond the camera thumbnail.
- Time limit: none documented for tasks.

### UserTesting (incl. UserZoom-era "Advanced" tasks)
Sources (snippets; help centre returns 403): https://help.usertesting.com/hc/en-us/articles/25569512843421-Inside-the-participant-experience-What-testers-see-and-do, https://help.usertesting.com/hc/articles/11880387288605, https://help.usertesting.com/hc/articles/11880303491869, https://help.usertesting.com/hc/articles/360000663738-Add-a-Skip-I-Don-t-Know-button, https://help.usertesting.com/hc/articles/360000672437, https://help.usertesting.com/hc/articles/35762064333725-Set-a-time-limit-for-participant-responses; https://www.wealthythrifter.com/how-to-pass-usertesting-practice-test/ (tester-side description)

- Task presentation: desktop tests use a tab structure, tasks on one tab and the asset on another, with the explicit promise that "testing prompts will never block testing assets". Tester guides describe tasks as on-screen prompts read one at a time.
- Controls: a "Next" button on the screen recorder advances tasks; "Done" replaces "Next" after the last task. Advanced (UserZoom-lineage) tasks can add a "Skip (I don't know)" button for prototype, tree and click tasks; navigation tasks have taskbar buttons where an "Abandon" click is recorded as abandon and can route to a separate "Abandon Questionnaire".
- Progress: task numbering via the recorder; no detail documented.
- Post-task questions: task types include verbal response, multiple choice, rating scale, written. "Task metrics" setting adds post-task Success and/or Difficulty follow-up questions the tester sees after the task.
- Consent and recording: contributors download the UserTesting Recorder, grant screen and mic permissions and pass an audio check before testing; mobile web studies run a step-by-step permission checklist and block testers who refuse required audio or camera. Clients can set a per-response time limit (article 35762064333725, not fetched).
- Task text re-openable: yes (it lives on its own tab).

### Lyssna (live website test, prototype test)
Sources: https://help.lyssna.com/en/articles/10456420-live-website-test-sections, https://help.lyssna.com/en/articles/5442240-prototype-test-sections, https://lyssna.com/blog/introducing-figma-prototype-tasks-with-lyssna

- Task presentation: live site tasks open in a new tab with instructions and follow-up questions in a floating picture-in-picture window. Prototype tasks show an intro screen, then a movable, minimisable modal whose starting position the researcher sets; custom instructions sit directly above the generic task instructions.
- Controls: live site "I'm done" (tasks never auto-end on reaching a URL). Prototype: optional success screen on goal reached; an "End task" button beneath the instructions "for participants who can't complete the task and need to give up". Researcher sets an estimated duration per live-site task; no enforced limit documented.
- Progress: multiple tasks run sequentially in the new tab, then the participant returns to the original tab; no indicator documented.
- Post-task questions: appear inside the same floating window/modal (task flow: after the goal screen or immediately if success screen is off; free flow: while still inside the prototype); conditional logic can branch on completed vs. not completed.
- Consent and recording: participants are told "recording is about to begin" and that a new tab will open; screen and audio recorded by default, camera optional; Chromium/Firefox desktop only; no in-task indicator documented.

### Useberry
Sources: https://www.useberry.com/website-usability-testing/, https://www.useberry.com/blog/website-usability-testing-all-you-need-to-know/, https://www.useberry.com/open-analytics/, https://useberry.nolt.io/26 (feature board, snippet only), https://infinum.com/handbook/design/tools/useberry

- Task presentation: participants "only see the instructions or the question itself" (Infinum handbook); the Zendesk help centre could not be fetched, so the panel geometry is unverified.
- Controls: a "give up" button exists (feature-board thread 26 asks for a separate "Skip task" alongside the existing give up, and reports give up "seems to end the whole test rather than the current task"); another request, "Make skip option more obvious", reports many participants do not see the skip button. Single Task completion is judged by path, URL or trigger element; Open Analytics tasks use self-report ("self-report when they believe the task is complete"). Tree tests distinguish direct skips (no exploration) from indirect skips.
- Post-task questions: survey blocks (opinion scale, Likert, SUS, open text) after tasks.
- Consent and recording: screen, voice, face recordings; an optional "legal consent screen" block can be added. No indicator documented.
- Progress, time limit: not documented.

### Loop11
Sources: https://www.canada.ca/en/loop11/instructions.html (a deployed study's participant instructions), https://www.experienceux.co.uk/ux-blog/loop-11-our-review/, https://www.loop11.com/setting-up-tasks/, https://www.loop11.com/faq/, https://www.loop11.com/privacy/, https://www.loop11.com/through-the-loop-case-study-airline-website-usability/task-completion-rate/ (help.loop11.com does not resolve)

- Task presentation: a fixed green task bar at the very top of every page; the task scenario is "always displayed at the top along with the progression buttons".
- Controls: "Task Complete" and "Abandon Task" in the bar. Canada.ca's instructions tell participants to click Abandon Task "if you can't find the answer" and reassure them "we are not evaluating you, we are evaluating the website". Abandonment is reported as a distinct outcome from failure.
- Task types: standard (no limit), time-bound (limit in seconds; the sample scenario says "if you can't find it within 2 minutes, note where you expected it"), first-click (closes after the first click).
- Progress: not documented.
- Questions: placed before or after any task, in sequence (shown as full pages, e.g. free text).
- Consent and recording: participants are asked at the outset whether camera/mic may record; "no recording will take place unless permission is granted by each individual participant"; screen share prompt ("Entire screen" then "Share"); the browser extension records only while the participant is in a study. Consent in the Canada.ca deployment is given by clicking Task Complete on the consent page.

### UXtweak (Website Testing)
Sources: https://blog.uxtweak.com/task-panel-in-website-testing/, https://blog.uxtweak.com/confirmation-of-completing-a-task/, https://www.uxtweak.com/help/website-testing-setup/tab-tasks/, https://www.uxtweak.com/help/website-testing-results/analysis-task-statistics, https://www.uxtweak.com/help/website-testing-guide/, https://www.uxtweak.com/features/replay-tasks-tool

- Task presentation: a collapsible task panel positioned at the top or bottom of the page (researcher's choice); respondents can hide it and can "read the task again in the panel throughout the study".
- Controls: a "done" button, which since the 2020 change opens a confirmation dialog so the task ends only after the respondent confirms (added because people "end tasks by accident" when stressed or clicking fast); an optional skip button (off by default: "Allow respondents to skip tasks"). Outcomes recorded: Success (ended on a success URL), Failure (ended elsewhere), Skip (pressed skip), Cancel (closed the task tab).
- Post-task questions: "appear immediately after each task", same builder as the questionnaire; answers can be voluntary or required.
- Consent and recording: screen, face and voice recording; welcome message and instructions are "the only way to guide participants"; the guide recommends stating duration, purpose and "no right or wrong answers". No in-task indicator documented.
- Progress, time limit: not documented ("Time Taken" is measured).

### Userbrain
Sources: https://kb.userbrain.com/help/how-do-i-start-with-my-example-test, https://kb.userbrain.com/help/what-and-when-is-the-chrome-extension-recording, https://kb.userbrain.com/help/how-do-i-record-my-tests, https://kb.userbrain.com/help/userbrain-chrome-extension-101

- Task presentation: no overlay on the page. The task lives in the Chrome extension popup; the tester clicks the pinned extension icon to read the current task and reopens it for each task. Mobile app: a "show task" button and "Finish Test" bottom-right.
- Controls: menu to pause or discard; "Finish recording and upload" appears on the last task; tester then reviews the recording and answers a few questions before upload. No give-up control documented; tasks are think-aloud narrative, success is coded from the video.
- Recording indicator: a timer in front of the extension icon shows elapsed recording time; recording starts only after "Open site and start recording" and stops on finish or exit.
- Consent: "Allow access" for mic, "Entire screen" share confirmation, several tip screens before start.
- Progress, questions, time limit: not documented beyond a 5 to 15 minute target length.

### Optimal Workshop (Prototype testing)
Sources: https://support.optimalworkshop.com/en/articles/10207780-getting-started-as-a-participant-with-video-recording, https://support.optimalworkshop.com/en/articles/9684897-adding-tasks-to-your-prototype-test, https://support.optimalworkshop.com/en/articles/9705997-how-to-analyze-your-prototype-test-results

- Task presentation: task shown alongside the prototype; participants "navigate until you think the task is complete".
- Controls: "Finish task" button (hidden when "Tasks end automatically" is on, in which case reaching the correct destination ends the task); optional skip per task ("useful when a task may not apply"). Results distinguish direct skip (immediate) from indirect skip (after clicking around, read as giving up or frustration).
- Consent and recording: browser prompts for camera, mic and screen; each can be allowed or declined; a confirmation page lists chosen permissions and shows a camera preview; recording starts only with the first task; a red recording icon appears top-left during the test; participants must keep the tab open until the upload bar finishes.
- Reassurance wording in the participant guide: "This is not a test of your ability, there are no right or wrong answers."
- Post-task questions: recommended per task for tasks without a correct answer; presentation not described. Progress, time limit: not documented.

### Reference point outside the list: Qualtrics unmoderated testing
https://www.qualtrics.com/support/survey-platform/survey-module/editing-questions/question-types-guide/specialty-questions/unmoderated-user-testing-question/ : live websites use "Launch task pane", a pop-up that stays on top until the session ends, with "Begin", a pause button, a stopwatch timer, and "Finish"; prototype tasks sit in a right-hand "Study Tasks" pane that can be hidden; sessions capped at 20 minutes.

## Part 2: Evidence

| Topic | Recommendation | Source |
|---|---|---|
| Scenario content | A task scenario needs context (why), an action to do in the interface (not describe), and all data needed to act (dates, names). Avoid step-by-step instructions, interface labels, forcing a feature, and vagueness. | NN/g, https://www.nngroup.com/articles/task-scenarios-usability-testing/ |
| Unmoderated wording | Instructions must be "specific, realistic, and actionable" without hints; tell participants explicitly when a task ends because nobody will move them on; pilot with real participants on their own equipment; audio think-aloud is essential, webcam secondary. | NN/g, https://www.nngroup.com/articles/unmoderated-usability-testing/ |
| Task visibility | Deliver one task at a time; participants should be able to see the instructions while they work "in case they forget"; having them read the task aloud confirms they read it fully. | NN/g, https://www.nngroup.com/articles/moderated-remote-usability-test/ and https://www.nngroup.com/articles/usability-testing-101/ |
| No prompting | In unmoderated sessions "there is no one there to remind her" to keep talking; any instruction that can be misread will be; stay reachable by email. | NN/g, https://www.nngroup.com/articles/remote-usability-tests/ |
| Self-reported completion | Self-reported completion averaged 93% vs. 33% verified (r = .24, 4 studies, 838 participants, 34 tasks); "almost three times higher". Do not use "Did you complete this task?" as a completion rate; verify by validation question (one correct answer, plausible distractors, an "other" option) or end URL; pair with time, SEQ and confidence. | MeasuringU, https://measuringu.com/self-reported-rates/ and https://measuringu.com/?p=586 |
| Confidence | After each task ask how confident the participant is that they completed it, 7-point, 1 least to 7 most confident. Completion rises with confidence (8% at 1, 77% at 7) but 23% of 7s failed; use for disaster rate (high confidence plus failure), never alone. | MeasuringU, https://measuringu.com/?p=171 |
| SEQ wording | Current stem: "Overall, how difficult or easy did you find this task?" (the older "Overall, this task was" is statistically equivalent); 7 numbered points, 1 = Very difficult (left) to 7 = Very easy (right); asked immediately after each attempt, including failed ones (about 14% of failed tasks are rated easy); mean benchmark about 5.5. Respondents prefer difficult-left and numbered; polarity and numbering barely change means. | MeasuringU, https://measuringu.com/seq10/, https://measuringu.com/evolution-of-seq, https://measuringu.com/comparison-of-two-seq-item-wordings/, https://measuringu.com/?p=41930, https://measuringu.com/seq/ |
| SEQ validity | SEQ correlates r = .66 with completion and r = -.53 with log task time; SEQ of 5.1 ≈ 68% completion, 6.3 ≈ 90%. Ask participants who rate below 5 to say why. | MeasuringU, https://measuringu.com/seq/, https://measuringu.com/seq10/ |
| Post-task questionnaire choice | Single-item SEQ performs as well as or better than SMEQ, UME and the 3-item ASQ; 7 steps beat 5; use at least 10 participants; ER (Albert & Dixon) asks "How difficult or easy do you expect this task to be?" before and "How difficult or easy did you find this task to be?" after. Tedesco & Tullis 2006 found one question as good as several. | Sauro & Lewis / Albert & Tullis as summarised at https://uxpsychology.substack.com/p/standardized-usability-questionnaires-ccb; https://measuringu.com/single-question/; Sauro & Dumas CHI 2009 https://measuringu.com/wp-content/uploads/2017/07/Sauro_Dumas_CHI2009.pdf |
| Time limits | A 60 s limit raised SUS 8 to 12% versus 5 s or no limit (256 participants); unmoderated task times differ from lab by about 30%; plan task time on the 75th to 95th percentile (TA tasks about 120 s); sessions typically 10 to 30 min. | MeasuringU, https://measuringu.com/?p=345, https://measuringu.com/?p=142, https://measuringu.com/online-study-time/ |
| Think-aloud in unmoderated tests | TA finds 36 to 50% more problems, takes about 20% longer, lowers SEQ and confidence about 5%, doubles dropout (50% vs 19%); only a third of task time has speech. Relaxed TA (with prompting/probing) changes behaviour and workload; classic TA mainly lengthens tasks. | MeasuringU, https://measuringu.com/ta-summary-2023/, https://measuringu.com/impact-of-ta-on-task-metrics/; Hertzum, Hansen & Andersen 2009, Behaviour & IT 28(2), https://orbit.dtu.dk/en/publications/scrutinising-usability-evaluation-does-thinking-aloud-affect-beha/ |
| Remote vs lab, asynchronous | Lab and remote completion and time correlate highly (Tullis et al. 2002); asynchronous remote methods find about half the problems of lab TA but at far lower cost (Andreasen et al. 2007; Bruun et al. 2009); predefined tasks beat participants' own tasks for problem discovery (Bruun & Stage 2012). | https://vbn.aau.dk/en/publications/what-happened-to-remote-usability-testing-an-empirical-study-of-t, https://vbn.aau.dk/da/publications/let-your-users-do-the-testing-a-comparison-of-three-remote-asynch, https://vbn.aau.dk/da/publications/the-effect-of-task-assignments-and-instruction-types-on-remote-as, review https://arxiv.org/pdf/1009.5918 |
| Skip / give-up | Always let participants give up: forced answers produce "garbage" results, make analysis harder, and participants dislike being forced more than they dislike giving up. | Observer and social-desirability bias | Observed participants try harder and tell researchers what they want to hear; frame the session as testing the product, not the person. | MeasuringU, https://measuringu.com/ut-bias/ and https://measuringu.com/task-completion/ |

## Synthesis

**(a) Dominant pattern for task presentation and controls.** Every product that runs on a live site shows the task in a persistent, compact overlay rather than a one-shot modal: Loop11 and UXtweak use a fixed strip (top, or top/bottom by researcher choice), Maze and Lyssna use a small draggable modal defaulting to a corner (bottom-left in Maze), Qualtrics a pop-up that stays on top. All tools read the task first on a full intro screen with a single start button ("Get started", "Begin", "Start testing"), then shrink it. The overlay can be collapsed ("Hide instructions") but never removed; UXtweak and NN/g both state the reason, that participants must be able to reread the task. Nobody stacks several tasks on screen. In-task controls are minimal: one affirmative end control ("Task Complete", "I'm done", "End task", "Finish task", "Done") and one give-up control ("Abandon Task", "Abandon task", "Stop task", "End task", "Skip"). Beyond those, only a drag handle, a hide/show toggle, and in recording products a mic mute and a pause. No product offers "back", and "pause" is a recording pause, not a task pause. Two guard-rails recur: Maze hides give-up until the participant has interacted once, and UXtweak confirms "done" before ending, because fast or stressed participants end tasks by accident. Progress across tasks is weakly documented everywhere; the only firm pattern is the next/done switch in UserTesting and a "Finish recording" button on the last task in Userbrain and Optimal Workshop. Time limits exist only as an opt-in task type (Loop11 time-bound tasks, UserTesting response limits, Qualtrics' 20-minute session cap); no product shows a "need more time" affordance.

**(b) Question screens.** Post-task questions are shown immediately after the task and in the same surface the task used: Lyssna and Maze inside the floating window or as the next block, UXtweak and Loop11 as the next page, UserTesting on the tasks tab. They are single questions per screen (opinion scale, multiple choice, open text), required by default with an optional "Skip" when the researcher allows it. The two standard questions products expose are Success (self-report) and Difficulty (SEQ-style scale).

**(c) Consent and recording.** The sequence is uniform: a pre-test note listing which of screen, mic and camera are required or optional; the native browser prompts; a confirmation page summarising what was granted (Optimal Workshop adds a camera preview, Maze a settings modal); a "Start" that begins recording only at the first task; and a visible, continuous indicator during the test (Optimal Workshop a red icon top-left, Userbrain an elapsed-time counter on the extension icon, Maze a camera thumbnail with mute and pause). Maze also shows a plain-language data warning when the session is not anonymised, and Loop11's deployment reassures "we are not evaluating you".

**(d) Evidence-backed rules.** The task card must carry context, one concrete action, and all data needed to perform it, without interface labels or steps (NN/g), and must say explicitly how the task ends (NN/g unmoderated). The bar must stay on screen and remain re-openable (NN/g, UXtweak), hold exactly a done control and a give-up control (vendor consensus, O'Brien), and must not carry a visible countdown unless time-bound by design, because limits shift ratings (Sauro). Done should confirm (UXtweak) and give-up should be unavailable until first interaction (Maze). SEQ: "Overall, how difficult or easy did you find this task?", 7 numbered points, 1 Very difficult left to 7 Very easy right, asked after every attempt including failures and give-ups, with a short "why" when the score is below 5 (MeasuringU). Confidence is asked only when completion cannot be verified by URL or validation question, as a 7-point item after the SEQ, and self-reported completion is never treated as a success rate (MeasuringU). Give-up wording should describe the situation, not the person, pair with "the site is being tested, not you", and be recorded as a distinct outcome so it is honest data rather than a failure the participant is coerced out of (O'Brien, MeasuringU bias, Loop11 deployment).

**(e) Minimal specification.**

1. *Scenario card* (full-screen before each task): title "Task 2 of 5"; scenario text of 2 to 4 sentences with context, action and data (NN/g); one line "When you think you've finished, press Done. If you can't find it, press I couldn't do this." (NN/g: tell them how the task ends); primary button "Start task" (Maze, Qualtrics).
2. *Task bar* (fixed bottom strip, draggable to top; UXtweak position choice, Maze default bottom-left): one-line task summary with "Show task" expanding the full card inline (UXtweak, Maze ">" button); "Done" opening a two-button confirm "Finished this task?" (UXtweak); "I couldn't do this" disabled until the first click or scroll (Maze), then recorded as "gave up" distinct from fail (UXtweak outcomes, Loop11 abandon); recording dot plus mic mute (Optimal Workshop, Maze); nothing else, no back, no timer by default (Sauro time-limit effect).
3. *Post-task screen* (same overlay, one question per step): SEQ as above (MeasuringU), then optional "What made it difficult?" when score ≤ 4 (MeasuringU seq10), then, only if the task has no success URL or validation question, "How confident are you that you completed the task?" 1 to 7 (MeasuringU confidence); each required unless the researcher marks it optional, which shows "Skip" (Maze).
4. *Consent and recording*: pre-test list of screen, microphone and camera with required or optional labels (Maze), native prompts, summary page with camera preview (Optimal Workshop), "the website is being tested, not you" and "you can stop at any time" (Loop11 deployment, Optimal Workshop participant guide), start recording at first task, continuous indicator with elapsed time (Userbrain) and mute/pause (Maze).
5. *Progress*: "Task n of N" on the card and bar; "Finish and upload" replaces Done on the last task (UserTesting Next/Done, Userbrain, Optimal Workshop upload bar).
