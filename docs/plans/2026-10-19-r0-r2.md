# ui-tests R0 to R2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `ui-tests` package and its mounts in `apps/web` so that R0 (rehearse a study on yourself), R1 (real people by link from CI, with a shareable report and a GitHub check) and R2 (the same file run by an agent, reported apart) work from a clean clone, offline, with `npm run validate` green after every task.

**Architecture:** One package, `packages/ui-tests` (CLI, compiler, lint, verifier, store adapters, collector, SDK, player, trace and report views, harnesses), added to the npm workspace beside `apps/web`. The author's app (`apps/web` for our own landing study) mounts the SDK component in its root layout and, in server mode only, the player route, the collector route and the report route; the landing keeps shipping as a static export. Hooks, paths and expected answers never leave the runner: the CLI bundles the study file into a hooks bundle stored with the run and executes it against stored snapshots. Every external service sits behind an interface with a local implementation used by the tests.

**Tech Stack:** Node 22.13+, TypeScript, Next.js 15 App Router, React 19, Zod 4 (with `z.toJSONSchema`), Ajv for wire validation of the published record schema, esbuild (hooks bundle), tsx (CLI runtime), linkedom (snapshot DOM), `playwright-core` (`request` for `setup`/`outcome`, screenshots, the web harness), `node:sqlite` (dev store), `@electric-sql/pglite` and `@neondatabase/serverless` (Postgres store), rrweb (event replay, lazy-loaded), `@modelcontextprotocol/sdk` (MCP server and harness), `@anthropic-ai/sdk` (one model provider, behind an interface), Vitest, Playwright, `@axe-core/playwright`.

**Spec:** `docs/prd/README.md` and `docs/prd/01-dx-contract.md` … `06-nonfunctional.md` (binding), `docs/story-map.md` (scope: every body card tagged `R0`, `R1`, `R2`), `docs/stack.md`, `docs/pitch.md`. `docs/issues/R0-walking-skeleton.md` is superseded and is reference only; commit `385975d` (`git show 385975d:packages/ui-tests/src/<file>`) is reference code to reuse where it fits; the PRD wins wherever they differ (notably the post-issue-#68 names).

**Static export and server mode (decision)**

- `<UiTests />` is mounted in `apps/web/app/layout.tsx` in both modes; without the `ui-tests-run` cookie it renders nothing and loads nothing.
- Every file under `apps/web` passes `tests/vocabulary.test.ts`: none of the `was` words (`SEQ`, `UX-Lite`, `gave up`, `timeout`, `deviation`, `dead click`, `incorrect`, `disconnected`, `panel` without "paid", "I can't do this", "I'm done", …). **Authoring contract (PRD 01, names after issue #68)**
- Authoring API, exactly: `study(name, options, fn)`, `setup(async ({ request }) => ({ start, ...values }))`, `task(name, { path, timeLimit, firstLook, start, minutes, primary, scenario, trials, reliability, target }, fn)`, `outcome(async ({ request, setup, page, workspace }) => …)`, `expect`, `participant.answer(...)`, `defineConfig(config)`. A `task` called inside a `task` body is a step: `task(name, check?)`.
- Old names are lint errors whose fix names the new one: `context`→`study`, `goal`→`task`, `beforeEach`→`setup`, `happyPath`→`path`, `catch`→`sample`, `video: true`→`record: 'video'`, `impression`→`firstLook`, a separate `screen` key → fields under `users`.
- Study options: `users` (string, or `{ are, did, within, often, role, uses, not, where, language, age }`, `are` required), `purpose`, `environment`, `sample: { affecting, confidence }` (default `{ affecting: 1 / 3, confidence: 0.85 }`), `record: 'video'`, `firstLook: false | { page }`, `independent: true`, `actors` (default `['human']`), `target`.
- Config file discovery: `ui-tests.config.{ts,mts,js}` first, then `vite.config.*` with a `uiTests` key; no config is valid and runs with defaults against `http://localhost:3000`. Keys: `target: { url, cli, mcp, http }`, `participants: { sources, budget: { max, currency } }`, `check: { block_on: 'problems', comment: false }`, `ci: { on: ['label:ui-test'] }`, `reporters: ['default', 'github-actions', 'json']`, `actor: 'human'`, `agents`, plus the decisions below (`product`, `author`, `brand`, `webhook`, `consent`).
- `init` writes `ui-tests.config.ts` and `ui-tests/invite.ui.test.ts`, byte-equal to `exampleFile` in `apps/web/lib/example.ts`, adds `*.ui.test.ts` to Vitest's exclude, and prints the three lines to mount.

**Derived values (PRD 01, 02)**
- n is the smallest integer with `1 − (1 − p)^n ≥ c`: `affecting: 1/3, confidence: 0.85` → **5**; `1/10, 0.85` → **19**.
- Goal timeout: `timeLimit`, else path-or-step count × **90 seconds**, floor **3 minutes**; silent, never shown as a countdown; the participant may ask for more time once.
- Impression ("First look"): flashed **500 ms**, open question **"What was that page for?"**, then one first click; codes **"named the purpose"**, **"did not name it"**, **"no answer"**; off when the start comes from `setup` unless `firstLook: { page }`.
- Questions: **"Overall, how difficult or easy did you find this task?"** (7-point), at **4 or below** **"What made it difficult?"**; confidence (7-point) only when the goal has neither `outcome` nor `participant.answer`; once after all goals **"Would {product} be useful to you?"**, **"{product} is easy to use."**, **"Anything you want to tell {product}?"**; UX-Lite item transform `(response − 1) × 25`. One question per screen, nothing preselected.
- Card and bar copy: card ends **"When you think you've finished, press Done. If you get stuck, press I couldn't do this."** and the button **"Start task"**; bar buttons **"Done"** (confirmed in place: **"Finished this task?"**) and **"I couldn't do this"**.
- Payout line: paid **"You can stop at any time and still be paid {amount}."**; unpaid **"You can stop at any time. This is unpaid."**
- Results: `problems-found` (f ≥ 1), `none-found` (f = 0 and u = 0), `inconclusive` (u > 0, or fewer than n attempts at the deadline); `pending` before. None-found sentence: **"Five people gave an 87% chance of seeing any problem that hits one in three; none was seen. That is not a completion rate."** Sample sentence in the trace: **"Five people give an 87% chance of seeing any problem that hits at least one person in three."** Rehearsal: **"Rehearsal: 0 of 5 planned attempts recorded."** (5 is n). Goal-only and path goals say "reached the outcome by their own route"; step goals "completed the steps".
- Terminal reasons (record values): `done`, `gave up`, `timeout`, `withdrew`, `disconnected`. Verified outcome: `correct`, `incorrect`, `unknown` with diff. A disconnected attempt is `disconnected`, never `incorrect`, and does not count toward n. Rehearsal attempts never count toward n.
- Single-attempt signals: dead click (nothing changed within **300 ms**), repeated click on the same target, pause over **5 seconds** with no input, URL off the path, backtrack, gave up / timeout, said Done but outcome `incorrect`, ease **3 or below**.

**Integration (PRD 05, 06)**
- Run handle fields: `run` (`r_` + ULID), `key`, `context: { users, purpose, id }`, `build: { url, commit }`, `actor`, `states: { recruitment: open|filled|paused|stopped, collection: waiting|collecting|complete, verification: pending|complete|instrumentation-problem, payment: none|reserved|paid|trued-up }`, `result: pending|problems-found|none-found|inconclusive`, `deadline` (default **48 hours** after start), `revision`.
- Idempotency key `${commit}:${contextId}:${actor}` (`recruit`; `--key` overrides); `check` uses `pr-${number}` in place of the commit. A repeated key returns the existing run.
- `recruit --wait` exit codes: **0** none found, **1** problems found, **3** pending or inconclusive, **2** error. `--json` keeps stdout for JSON and stderr for diagnostics.
- `--actor both` is refused. Check names **`ui-tests`** (human) and **`ui-tests (agent)`**. Titles: **"{n} problems found · {x} of {n} people reached the goal"** ("1 problem found" for one), **"No problems found with {n} people · {x} of {n} reached the goal"**, **"Inconclusive · only {x} of {n} attempts completed"**. Conclusion `neutral` always, `failure` only with `block_on: 'problems'` and a completed run with problems; never `success`. Page line: **"This check never fails your build. It reports problems, or that none were seen this time."**
- `host` prints its plan and exits 2 with **"host: not shipped yet; see https://github.com/miguel-perez/ui-tests/issues/59"**.
- Share links: path signed with HMAC-SHA256 under **`UI_TESTS_SHARE_SECRET`**; without the secret there are no share links; unsigned or altered → 404. Report at **`/r/<run>`**, attempt at **`/r/<run>/p<n>`**.
- Cookie **`ui-tests-run`**; player route **`/ui-tests/[run]`**; collector **`/api/ui-tests/`**. The collector accepts writes only with a participant token scoped to one run, or the CLI secret `UI_TESTS_CLI_SECRET`.
- Store selection: `UI_TESTS_DATABASE_URL` = `postgres://…` (Neon), `pglite:memory` or `pglite:<dir>` (PGlite); unset → SQLite at `${UI_TESTS_DATA_DIR ?? '<repo>/.ui-tests'}/dev.sqlite`. Amounts in integer minor units with a currency; reservation is transactional.
- Retention default **90 days**; withdrawal deletes recordings. Participant identity and the device/IP hash are never exported. Player bundle has no hooks, paths, expected answers or credentials.
- White label: no ui-tests name, logo or link on any participant-facing surface unless `brand.poweredBy: true` (default false); colours from the host via CSS variables with a neutral fallback.
- Agents (PRD 04): `trials` default **5**; `reliability: 'all'` default (pass^k), `'any'` (pass@k); trial states `verified`, `stopped`, `unknown`; reporter heading **"capability test, not usability"**; a study on `target.cli|mcp|http` that lists `human` fails lint.

**Decisions taken where the spec is silent** (each also listed in the hand-off): config `product` (the name in UX-Lite questions and the product-name lint; default the target hostname); config `author` (string) and `brand: { accent?, poweredBy? }`; config `webhook: { url, secret }`; config `consent: { workflows: boolean }` adds the third purpose; nested `task` as a step; `participant.answer(question, { expected, distractors? })` registered in the task body, asked after Done; `setup` runs in the runner once per invite slot when `recruit` creates the run; revisions are made in the local trace viewer, not a new CLI command; MCP `estimate` returns n and minutes only until R3.

## Review Focus

1. **A study file that throws or fails to parse** — the person expects `ui-tests lint`/`ui-tests` to print the file and line and exit 2 without creating a run. Pinned in Task 2 and Task 13.
2. **A participant closes the tab or loses the connection mid-attempt** — the attempt becomes `disconnected` (not `incorrect`, not counted toward n), and buffered events replay if the page comes back. Pinned in Task 7 and Task 9.
3. **Done pressed twice, or Done racing the time limit** — one end is stored; the second request is refused without changing the snapshot or reason. Pinned in Task 8.
4. **The target is not reachable when dev mode or `recruit` starts** — exit 2 with "target not reachable: {url}" before any run exists. Pinned in Task 14 and Task 17.
5. **A very large page** (end-state DOM over 2,000,000 characters, or event batches over 100) — the recorder truncates and flags the snapshot, the collector answers 413 to oversize bodies, and a hook that cannot find its element on a truncated snapshot returns `unknown`. Pinned in Task 8 and Task 9.
