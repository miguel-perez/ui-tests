# Captures

Captured with Playwright Chromium on the light theme, reduced motion on, so the page's texture holds one still frame. The site is light only: it renders these same colours under a dark system setting; the Tokyo Night block in `design/artefacts/tokens.css` is the artefact viewer's dark alternate, not the site's.

The landing, regenerated by the e2e suite:

```sh
PLAYWRIGHT_BROWSERS_PATH=0 CAPTURE_SITE=1 npm run test:e2e
```

[Landing at 1440](landing-1440.jpg) · [landing at 375](landing-375.jpg)

The grid test (`tests/e2e/grid.spec.ts`) writes its readings to `test-results/grid-readings.json`; one run is kept as
[`grid-test-readings.json`](grid-test-readings.json): each section's heading and lead left edges and its figures' left edges and widths
at 1440 and 375, and the page heights.

The block captures in `blocks/` measure every block of the landing at both widths against [`docs/design/grid-plan.md`](../../docs/design/grid-plan.md).
The suite does not regenerate them; with a running site on port 3000:

```sh
PLAYWRIGHT_BROWSERS_PATH=0 UI_HARNESS_ROOT=/path/to/ui-harness node apps/web/scripts/measure-blocks.mjs
```

That writes `blocks/<page>-<block>-<width>.png` (blocks L1 to L7 on the landing, as named in the plan)
and [`grid-readings.json`](grid-readings.json): each block's placed-content area against its empty area (the plan's rule:
empty never exceeds content), and the ui-harness layout rows computed by the register's own `harness.layout.layout_metrics`
on the block's leaf boxes (grid quality, balance, density, white space, regularity). The harness readings are feedback, not a
gate. Its white space counts the inside of every window as white, because a window with children is not a leaf; the plan's
empty-area rule counts the placed artefacts whole.

`../screens-d2/` holds the hero and artefact explorations, stills and motion; the approved markup is in `../artefacts/`.
